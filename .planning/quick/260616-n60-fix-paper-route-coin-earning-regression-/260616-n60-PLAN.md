<objective>
Fix the paper-route coin-earning regression: coins earned in the PaperThrowScene mini-game are added to `this.coins` and saved, but the HUD counter never moves because `enterMiniGame()` never emits `Events.COINS_CHANGED`. The player experiences this as "can't earn coins."

Root cause (already investigated — do NOT re-investigate): `OverworldScene.enterMiniGame()` (src/game/scenes/OverworldScene.ts, lines 508-522) handles `Events.MINIGAME_COMPLETE`, does `const earned = result.score * 2 + result.perfect * 3; this.coins += earned;`, then `triggerSystem.release` + `SaveService.save` — but NEVER emits `Events.COINS_CHANGED`. Every other coin mutation in this file emits it (shop line 120, prize-pack 717, streak 742, patience 810, hospital 849, traversal 889). The HUD (`UIScene.onCoinsChanged`) only updates on `COINS_CHANGED`. The reward formula was always correct — the missing EMIT is the bug.

Approach: route the award through an INJECTABLE emitter in pure-TS Economy.ts (mirroring how PrizePack.ts injects `rng`) so a node test can assert the emit happens. A pure formula test alone would NOT catch this regression.

Purpose: Restore the core paper-route earning loop and guard it against recurring.
Output: Two pure-TS Economy helpers, a one-line wiring change in OverworldScene, and a regression test.
</objective>
