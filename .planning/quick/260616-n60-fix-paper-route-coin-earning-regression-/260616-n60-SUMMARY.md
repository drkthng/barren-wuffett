# Quick Fix 260616-n60: Fix Paper-Route Coin-Earning Regression Summary

**One-liner:** Injectable `awardMinigameCoins` helper routes paper-route reward through `COINS_CHANGED` so the HUD coin counter updates on every mini-game completion.

## What Was Done

### Root Cause (confirmed pre-investigation)

`OverworldScene.enterMiniGame()` computed `earned` and incremented `this.coins` but never emitted `Events.COINS_CHANGED`. Every other coin mutation in the file emits it; the HUD (`UIScene.onCoinsChanged`) only updates on that event. The player's coin total was being saved correctly but the HUD counter never moved — appearing as "can't earn coins."

### Task 1: Economy helpers + OverworldScene wiring (commit `4f8bd7e`)

**src/systems/Economy.ts** — added two exported functions following the file's existing JSDoc/pure-TS style:

- `computeMinigameReward(score, perfect): number` — paper-route reward formula: `score * 2 + perfect * 3`. Named helper so the formula has a single source of truth.
- `awardMinigameCoins(coins, result, onCoinsChanged): number` — computes earned via `computeMinigameReward`, computes `newCoins = coins + earned`, calls `onCoinsChanged(newCoins)` unconditionally (even when earned === 0), returns `newCoins`. Emitter is injected, not imported — Economy.ts stays Phaser-free and node-testable (mirrors PrizePack.ts `rng` injection pattern).

**src/game/scenes/OverworldScene.ts** — two changes:

1. Extended Economy import (line 34): `import { computeHospitalFee, applyPurchase, awardMinigameCoins } from '../../systems/Economy';`
2. Replaced the two bare-assignment lines in `enterMiniGame()` MINIGAME_COMPLETE handler with:
   ```ts
   this.coins = awardMinigameCoins(this.coins, result, (n) => GameEvents.emit(Events.COINS_CHANGED, n));
   ```
   The existing `triggerSystem.release` and `SaveService.save` calls were left in place unchanged. `enterBoss()` was not touched (out of scope per plan).

**Verification:** `npm run check` (tsc --noEmit) and `npm run build` (vite) both pass with no errors.

### Task 2: Regression test (commit `6a7ec1c`)

**tests/minigame-reward.test.ts** — 7 tests, vitest node env, no Phaser, same import convention as `shop-economy.test.ts` (`await import('../src/systems/Economy.js')` with .js extension):

- `computeMinigameReward` formula: (5,0)→10, (5,5)→25, (3,1)→9, (0,0)→0
- `awardMinigameCoins` returns correct new total
- **Regression guard:** spy asserts injected emitter called exactly once with the new total (14) — this assertion would have caught the original bug immediately
- **Zero-earn guard:** emitter still called once when earned===0 so HUD remains authoritative

**Verification:** `npm test` — 128 tests across 16 suites, all green.
