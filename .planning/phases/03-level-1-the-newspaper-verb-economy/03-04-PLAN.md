## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ShopOverlay (UIScene) → OverworldScene | Purchase requests cross via SHOP_PURCHASE; OverworldScene is the authoritative validator (coins/flags). UIScene never mutates coins. |
| IndexedDB → OverworldScene | `coins`/`flags` loaded on init (SaveService.migrate-normalized); new upgrade flags read via truthiness; gate state restored from `upgrade_traversal`. |

Client-side only; no network, no eval of shop/dialogue data (static JSON imports), no new fetch/supabase (SAVE-02 preserved). No payments — coins are in-game only (Out-of-Scope: no IAP).

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Tampering | Client-side purchase with insufficient/owned state | mitigate | All purchases validated by `Economy.applyPurchase` in OverworldScene (authoritative); UIScene only requests. Owned permanents and `coins < price` return null → no deduction. (No backend to protect; coins are non-monetary.) |
| T-03-11 | Elevation of Privilege | Shop event feedback loop re-opening/re-rendering on purchase | mitigate | Per Pitfall 3, COINS_CHANGED only updates the HUD; the panel refresh re-emits SHOP_OPEN with fresh payload (data refresh, not a state re-toggle); UIScene ignores SHOP_OPEN while already SHOP-state except to re-show data. |
| T-03-12 | Denial of Service | Player movement while shop/hospital open | mitigate | OverworldScene.update() early-returns on `shopOpen || hospitalShowing` (Pitfall 7); scene also paused by UIScene. |
| T-03-13 | Tampering | Zombie SHOP/HOSPITAL listeners after restart | mitigate | Every GameEvents.on() has a matching off() in shutdown() (CR-03 / Pitfall 4) for both UIScene and OverworldScene. |
| T-03-SC | Tampering | npm installs | accept | Zero new packages (RESEARCH Package Legitimacy Audit — all approved). |

No high-severity threats. This is a local browser game with in-game-only currency and IndexedDB-only persistence.
