# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3: Level 1 — The Newspaper Verb & Economy.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **Scope:** Six new Phaser canvas UI components added to the existing system:
> (1) on-screen Whack Button (touch), (2) Whack feedback — swing arc, bush-clear
> particles, coin "+N" float, (3) Snowball coin HUD extensions — COINS_CHANGED wiring,
> "+N" pickup float, streak indicator, streak-bonus flash, (4) SHOP overlay — new UIScene
> state listing 4 purchasable items with affordability/ownership states, (5) HOSPITAL
> splash — new UIScene state shown on dog-bite respawn, (6) Dog-bite hazard feedback —
> knockback tween + i-frame sprite flash.
>
> **ALL existing design tokens are LOCKED — inherited from Phase 1 and Phase 2 UI-SPECs.
> This document specifies ONLY the new Phase-3 components. Do not re-implement or alter
> the existing HUD, DialogueBox, PauseMenu, BossScene UI, or PaperThrowScene HUD.**
>
> All UI is rendered to a Phaser 4 canvas. No React, no shadcn — Phaser GameObjects only.

## Component Inventory (Phase 3 New Components Only)

### 1. Whack Button (touch only, right-thumb zone)

**Owner:** UIScene (same depth layer as VirtualJoystick — above tilemap, below dialogue box)

**Position:**
- Center: `x=360, y=750` (portrait canvas; 240px right of joystick at 120,750)
- Input zone: 64x64px (`setInteractive({ useHandCursor: false, hitArea: new Phaser.Geom.Rectangle(-32,-32,64,64) })`)
- Visual: 48x48px sprite `newspaper_button` (the rolled-up newspaper icon), centered in zone

**Visual states:**

| State | Appearance |
|-------|------------|
| Idle | `newspaper_button` sprite at alpha 1.0, no border tint |
| Pressed (pointerdown) | alpha 0.7, scale 0.9 × 0.9 (100ms squish tween, ease `Power2`) |
| Cooldown (~300–400ms after whack) | alpha 0.45; no interaction during cooldown |
| Released (pointerup or cooldown end) | alpha 1.0, scale 1.0 (restore tween, 80ms) |

**Border:** 2px stroke `#00ff88` on the outer 64px zone area (always visible — signals this is the whack action).

**Visibility:** Touch devices only (`this.sys.game.device.input.touch === true`). Hidden on desktop (keyboard-only: `Space`/`J` keys via InputBus).

**Keyboard contract:** `J` key is the always-whack key (fires `Action.WHACK` unconditionally). `Space`/`Enter` whacks only when no NPC in interact range (the existing `handleInteract` gate). Both keys give identical game response to the button; no on-screen indicator needed for keyboard (desktop secondary).

**Collision-avoidance note:** The 64px input zone at `(360,750)` has its left edge at `x=328`. The VirtualJoystick at `(120,750)` with 80px radius has its right edge at `x=200`. Separation is 128px — safe on minimum 320px-wide device.

### 2. Whack Feedback

All feedback is rendered in OverworldScene (not UIScene) at the player's world position.

**2a. Newspaper swing arc (the verb signal)**

- Asset: `newspaper_swing` sprite sheet — 3 frames, each 32x32px, in a horizontal strip (96x32px PNG-8).
  Frame 0: newspaper at rest angled forward; Frame 1: mid-arc (45° rotated); Frame 2: full arc (90° rotated).
- Phaser animation: `newspaper_swing_anim` — 3 frames at 18 fps (total ~167ms), no repeat, `hideOnComplete: true`.
- Anchor offset: the swing sprite is positioned 20px in front of the player based on `facing`:
  - down: `(player.x, player.y + 20)`
  - up: `(player.x, player.y - 20)`, sprite flipY
  - left: `(player.x - 20, player.y)`, sprite flipX
  - right: `(player.x + 20, player.y)`
- Depth: player sprite depth + 1 (renders on top of player)
- No color tint on the swing sprite.

**2b. Bush-clear particle burst**

- Trigger: fires at the bush sprite's position (`bush.x`, `bush.y`) when the bush is hit.
- Phaser 4 particles (`this.add.particles()`): emit a one-shot burst.
  - Texture key: `leaf_particle` (8x8px PNG-8, single green leaf shape)
  - Burst count: 6 particles
  - Speed: random 40–100 px/s
  - Angle: all 360° (omnidirectional puff)
  - Scale: start 1.0, end 0.0 over lifetime
  - Lifespan: 400ms
  - Alpha: start 1.0, end 0.0 over lifetime
  - Gravity: 80 px/s² (fall slightly downward)
- On emission, bush sprite immediately calls `setVisible(false)`. The particle burst is the "clear" moment — no intermediate bush-shake animation is required for MVP (bush shake is listed as optional polish in D-03 and can be added in Phase 5).

**2c. Coin "+N" pickup float (snowball juice)**

- Trigger: fires at `(player.x, player.y - 24)` immediately when coins are awarded from a whack.
- Renders in UIScene (same world as HUD, depth 25) — reuses `HUD.flashCoinPickup(amount)`.
- Text: `+{n}` where n is the coin amount (1, 3, or 5 — from prize-pack slots).
- Font: Label 8px, color `#f5c842` (coin gold), `"Press Start 2P", monospace`.
- Tween: `y` from canvas Y equivalent of player position → -40px offset over 700ms; `alpha` 1.0 → 0.0 over same duration. Destroy on complete.
- For snack drops (no coin): show `+SNACK!` in `#e8e8e8` instead, same float pattern.
- Multiple simultaneous floats are allowed (each is its own Phaser Text object, independent tween).

**2d. On-hit flash (optional secondary confirmation)**

- When a whack connects with a bush: the bush sprite flashes white alpha 0.5 for 80ms (a single Phaser `setTintFill(0xffffff)` then `clearTint()` via `time.delayedCall(80, ...)`) before hiding.
- This is the only color tint operation on any whackable bush sprite.

### 3. Snowball Coin HUD Extensions

The existing coin counter at `x=16, y=16` in UIScene is the "snowball" — its running
total is the compounding-theme metaphor. Phase 3 closes the HUD↔coins gap (D-08)
and adds the streak indicator below it.

**3a. COINS_CHANGED wiring (D-08 — closes the existing gap)**

The HUD coin counter currently never updates because nothing calls `HUD.setCoins()`.
This is the highest-priority visual contract item.

- `UIScene.create()` registers: `GameEvents.on(Events.COINS_CHANGED, this.onCoinsChanged, this)`.
- `onCoinsChanged(n: number)`: calls `this.hud.setCoins(n)` AND `this.hud.flashCoinPickup(n - previousCoins)` where `previousCoins` is the last known value stored in UIScene.
- `UIScene.shutdown()` deregisters: `GameEvents.off(Events.COINS_CHANGED, this.onCoinsChanged, this)`.
- The coin number text color is `#f5c842` (coin gold), not `#e8e8e8`. Update the existing `COINS: {n}` text to use `#f5c842` for the `{n}` portion only; `COINS:` label stays `#e8e8e8`.
- The existing scale-up tween (1.0 → 1.2 → 1.0 over 150ms) on increment remains unchanged.

**3b. Streak indicator**

A new HUD sub-element rendered below the coin counter, visible only when at least one
bush has been whacked since the last dog hit (streak > 0).

- Position: `x=16, y=40` (8px below coin counter base at y=16+16px text = y=32; +8px gap)
- Label: `t('hud.streak')` → `STREAK:` at Label 8px, `#e8e8e8`.
- Streak pips: 8 Phaser Rectangle objects, each 12x8px, gap 4px, starting `x=72, y=40`.
  - Total bar width: 8 × 12px + 7 × 4px = 124px. Fits within left HUD area (x=16 to x=196).
  - Filled pip color: `#00ff88` (accent) — earned progress.
  - Empty pip color: `#16213e` (secondary) — remaining.
  - All 8 pips lit = streak threshold reached. The bonus fires on the 8th whack.
- Visibility: `setVisible(streak > 0)`. Hidden at game start and after dog bite resets streak.
- Update pattern: `UIScene` listens for a `BUSH_WHACKED` event carrying `{ streak: n }`;
  updates pip fill states accordingly.

**3c. Streak-bonus flash**

- Trigger: `GameEvents.STREAK_BONUS` emitted by OverworldScene when the 8-bush milestone yields
  the bonus pile (8 coins) or a Journal page.
- Flash behavior: centered at `x=240, y=200`.
  - Line 1: `t('hud.streakBonus')` → `STREAK BONUS!` at Heading 16px, `#00ff88`.
  - Line 2: `+8 COINS` (or `JOURNAL PAGE!` for special bushes) at Body 8px, `#f5c842`.
  - Duration: 1.2 seconds total. Alpha 0.0 → 1.0 over 120ms, hold for 800ms, alpha 1.0 → 0.0 over 280ms.
  - `y` tween: drifts from 200 to 168 over 1.2s (same float pattern as patience bonus).
  - Destroy on complete.

### 4. SHOP Overlay (new UIScene state: `SHOP`)

**State machine addition:**

```
UIState = 'HUD' | 'DIALOGUE' | 'PAUSE' | 'LEVEL_COMPLETE' | 'SHOP' | 'HOSPITAL'
```

Transition: `HUD → SHOP` on `GameEvents.SHOP_OPEN` (emitted by OverworldScene when the
Store Clerk dialogue resolves). `SHOP → HUD` on `GameEvents.SHOP_CLOSE` (Close button tap
or ESC). OverworldScene is paused via `this.scene.pause('OverworldScene')` on shop open
and resumed on close.

**Backdrop:**
- Full-canvas `#000000` Rectangle, alpha 0.6, Z-depth above all game content. Same as
  existing pause menu backdrop.

**Panel geometry:**
- Center: `x=240, y=427` (canvas center)
- Size: 320px wide × 380px tall
- Fill: `#1a1a2e`; stroke: `#e8e8e8` 2px
- Corner: sharp (no cornerRadius — pixel-art convention, consistent with pause panel)

**Panel layout (panel top = 427 - 190 = 237, panel bottom = 617):**

```
y=261  SHOP                              [Display 24px, #e8e8e8, centered at x=240]
y=309  [divider: 280px wide, 1px, #16213e, centered]
y=325  [item row: Sunday Edition]        [see item row spec]
y=373  [item row: Bike Helmet]
y=421  [item row: Bus Pass]
y=469  [item row: Snack]
y=525  [divider: 280px wide, 1px, #16213e]
y=557  CLOSE                             [Heading 16px, #e8e8e8, 280×44px hit zone]
```

**Item row spec (each row is 48px tall — touch target):**

Each row is a Phaser Container at the row's Y position, centered at `x=240`.
Row width spans the panel interior (280px, padded 16px inside the 320px panel).

```
[row content, left-to-right, within 280px:]
  [item icon]   16x16px sprite, left-aligned at row x=168 (panel left + 16px padding)
  [item name]   Heading 16px, #e8e8e8, x=192 (icon right + 8px gap), y=row center
  [price block] right-aligned at x=448 (panel right - 16px):
                  coin icon 8x8px + Body 8px price text in #f5c842 — e.g. "20" next to coin
  [action]      Heading 16px, see affordability states below, right of price or replacing it
```

**Item affordability and ownership states:**

| Condition | Price text | Action label | Action color | Row alpha |
|-----------|-----------|--------------|--------------|-----------|
| Affordable, not owned | `#f5c842` coin+price | `BUY` | `#00ff88` | 1.0 |
| Not affordable, not owned | `#ff4444` coin+price (crossed out via strikethrough not available in Phaser — use `#ff4444` color as signal) | `BUY` | `#e8e8e8` alpha 0.5 | 0.7 |
| Owned (permanent upgrade) | (hidden) | `OWNED` | `#e8e8e8` | 0.9 |
| Snack (consumable, always available if affordable) | `#f5c842` coin+price | `BUY` | `#00ff88` | 1.0 |

Note: The "Snack" row never shows OWNED (it is consumable). After purchase it refreshes
with the same BUY state if the player still has enough coins for another (but Snack has
an immediate consumable effect and is not re-buyable in the same shop visit — the shop
re-opens in a fresh state each time via `SHOP_OPEN` payload).

**On BUY tap:**
- Immediately emit `GameEvents.SHOP_PURCHASE({ itemId, price })` to OverworldScene.
- OverworldScene validates and emits `COINS_CHANGED` + re-emits `SHOP_OPEN` with updated
  `{ coins, flags }`. UIScene re-renders the panel (replaces shopOverlay.show() with fresh data).
- Button press feedback: alpha 0.7 for 100ms (same pattern as all other buttons).

**"Not enough coins" feedback:**
- If the player taps a BUY button on a row they cannot afford: do NOT emit SHOP_PURCHASE.
  Instead, flash `t('shop.notEnoughCoins')` → `NOT ENOUGH COINS` below the panel at
  `x=240, y=625`, Body 8px, `#ff4444`, for 800ms (fade out tween). The row shakes
  horizontally: `x` tween ±4px, 3 cycles, 80ms per cycle.

**CLOSE button:**
- Position: `x=240, y=557` (center of button)
- Size: 280px wide × 44px hit zone
- Label: `t('shop.close')` → `CLOSE`, Heading 16px, `#e8e8e8`
- On press: emit `GameEvents.SHOP_CLOSE`; UIScene setState('HUD'); resume OverworldScene.
- Button feedback: alpha 0.7 for 100ms on pointerdown.

**CLOSE keyboard shortcut:** ESC key fires `GameEvents.SHOP_CLOSE` (same as the existing
PAUSE keyboard shortcut binding pattern — add to UIScene keyboard handler).

### 5. HOSPITAL Splash (new UIScene state: `HOSPITAL`)

**Trigger:** `GameEvents.PLAYER_HOSPITALIZED` emitted by OverworldScene after dog bite
knockback completes. The hospital beat is the gag — cozy and funny, never punishing.

**Duration:** Auto-dismiss after 1500ms. Also dismisses on `pointerdown` anywhere on canvas
(standard UIScene pattern — see `time.delayedCall` in RESEARCH.md Pattern 4).

**Scene pause:** OverworldScene is paused via `this.scene.pause('OverworldScene')` on
`PLAYER_HOSPITALIZED`, resumed on dismiss. Player input is disabled during the splash.

**Panel geometry:**
- Center: `x=240, y=427` (canvas center)
- Size: 360px wide × 220px tall
- Fill: `#1a1a2e`; stroke: `#e8e8e8` 2px
- Panel top: 427 - 110 = 317; panel bottom: 537

**Panel layout:**

```
y=349  WAKE UP IN HOSPITAL!          [Display 24px, #e8e8e8, centered at x=240]
         (two lines if needed:        WAKE UP IN
                                      HOSPITAL!
         word-wrap at 280px)
y=405  [coin deducted line]          [Body 8px, #ff4444, centered]
         e.g.  HOSPITAL FEE: -5 COINS
         (if helmet owned: shown in #00ff88 instead)
         e.g.  HELMET BLOCKED THE FEE!
y=433  TAP OR WAIT TO CONTINUE       [Label 8px, #e8e8e8 alpha 0.6, centered]
```

**Coin-fee display logic:**
- If `upgrade_helmet` flag is true: show `t('hospital.helmetBlocked')` → `HELMET BLOCKED THE FEE!` in `#00ff88` (positive outcome signal).
- If `upgrade_helmet` flag is false and coins ≥ 5: show `t('hospital.fee')` → `HOSPITAL FEE: -5 COINS` in `#ff4444`.
- If `upgrade_helmet` flag is false and coins < 5 (floor to 0): show `t('hospital.feeLow')` → `HOSPITAL FEE: -0 COINS (BROKE!)` in `#ff4444` (humor — not a genuine punishment).
- The fee amount is passed in the `PLAYER_HOSPITALIZED` event payload: `{ fee: number, helmetOwned: boolean }`.

**Tone:** The heading is ALL-CAPS pixel-game voice, deliberately oversized for comic effect.
The sub-lines keep the non-punitive framing. There is no skull, no "GAME OVER", no red
screen flash. The panel appears with a brief scale-in tween (0.7 → 1.0 over 200ms,
ease `Back.Out`).

**On dismiss:** UIScene `setState('HUD')`, resume OverworldScene. OverworldScene respawns
player at `(96, 96)` (this is handled in OverworldScene, not UIScene).

### 6. Dog-Bite Hazard Feedback

All feedback is rendered in OverworldScene on the player sprite (not UIScene).

**6a. Knockback tween (D-10)**

- Trigger: OverworldScene detects player↔dog overlap while `!player.isInvincible`.
- Physics body disable: `player.sprite.body.moves = false` before tween starts;
  re-enable in `onComplete`.
- Tween: `x/y` tween away from dog position, distance ~48px, over 180ms, ease `Power2`.
- No camera shake. No screen tint. Pure position movement only.

**6b. I-frame flash (D-10)**

- Duration: 900ms total (6 × 80ms yoyo cycles: 80ms fade to alpha 0 + 80ms restore = 160ms per
  cycle × 6 = 960ms — close enough to the 0.8–1.0s target from D-10).
  Use: `tweens.add({ targets: player.sprite, alpha: 0, duration: 80, yoyo: true, repeat: 5 })`.
- After tween ends: `player.sprite.setAlpha(1)` and `player._invincible = false`.
- No color tint during i-frames — alpha oscillation only (preserves sprite art integrity).
- Knockback tween and i-frame flash are sequential: knockback runs first (180ms), then i-frame
  flash starts in `onComplete` callback.

**6c. Dog-bite SFX (contract note)**

- SFX key: `dog_bite` — plays via `AudioService.playSfx('dog_bite')` in OverworldScene
  at the moment of contact detection.
- No visual for the SFX; it is purely audio.

## UIScene State Machine (updated)

Phase 3 extends the existing 4-state machine to 6 states.

```
UIState = 'HUD' | 'DIALOGUE' | 'PAUSE' | 'LEVEL_COMPLETE' | 'SHOP' | 'HOSPITAL'
```

**Transition table:**

| From | Event | To | Side effect |
|------|-------|----|-------------|
| HUD | DIALOGUE_START | DIALOGUE | HUD hidden |
| DIALOGUE | DIALOGUE_COMPLETE | HUD | HUD shown |
| HUD | PAUSE_REQUESTED | PAUSE | OverworldScene paused |
| PAUSE | RESUME_REQUESTED | HUD | OverworldScene resumed |
| Any | BOSS_DEFEATED | LEVEL_COMPLETE | All game scenes stopped |
| HUD | SHOP_OPEN | SHOP | OverworldScene paused; shop panel shown |
| SHOP | SHOP_CLOSE | HUD | OverworldScene resumed; shop panel hidden |
| HUD | PLAYER_HOSPITALIZED | HOSPITAL | OverworldScene paused; hospital splash shown |
| HOSPITAL | (auto 1500ms or tap) | HUD | OverworldScene resumed; player respawned |

**setState() visibility contract (extends existing):**

## Scene-by-Scene Interaction Contract (Phase 3 additions)

### OverworldScene (extended)

**New input sources:**
- Whack Button pointerdown → `InputBus.setAction(Action.WHACK, true)`
- Whack Button pointerup → `InputBus.setAction(Action.WHACK, false)`
- `J` key → `InputBus.setAction(Action.WHACK, true)` (unconditional)
- `Space`/`Enter` → WHACK only when no NPC in interact range (existing gate)

**New movement block conditions:** Player movement (`InputBus` polling) is blocked
during `inHandoff || inDialogue || isInvincible || inShop || inHospital`. The last two
conditions are new flags; OverworldScene reads them by checking UIScene state or via
a dedicated flag: `this.shopOpen` / `this.hospitalShowing`.

**Dog patience-gap reward preserved (GAME-06):** The existing `dogGapActive` coin bonus
(the patience-gap window) continues to fire. The bite hazard is additive — the dog is
now both a patience reward and a contact hazard, not one or the other (D-09).

**Autosave triggers (extended):** Add: after any shop purchase, after hospital dismiss.

All handlers registered in `create()` and deregistered in `shutdown()` (the CR-03

### Empty States

No list views in Phase 3. The shop always has 4 items — no empty state needed.
The coin counter at 0 is valid state (not an error). No empty state copy required.

### Destructive Actions

No destructive actions in Phase 3. Shop purchases use the player's coins, but:
- The purchase is confirmed by a simple tap (no second confirmation dialog) — coins are
  not high-stakes enough to warrant a confirmation modal in a casual game context.
- All upgrades are permanent and positive — no irreversible negative action.
- The "not enough coins" guard prevents accidental purchases.

This is consistent with the Phase 2 pattern: only "QUIT TO MENU" (data loss risk) needed
a confirmation. No Phase 3 action rises to that level.
