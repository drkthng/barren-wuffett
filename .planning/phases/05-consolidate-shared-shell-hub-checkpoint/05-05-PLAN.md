<objective>
Make every page CSP-clean with cookieless Cloudflare Web Analytics (MEAS-01, SHELL-06), derive the build entries from the game registry so each later release only flips a flag and adds an entry (HUB-02, ROADMAP SC2), give unknown paths a real 404, and rewrite the privacy page to match reality in German and English (LEGL-05, D-17).

Purpose: the analytics beacon is the only third party this site may contact, and a CSP mismatch fails silently (PITFALLS 8). The privacy page is legally load-bearing; the current one still lists Supabase and Brevo and says there is no analytics.

Wiring choice (Claude's discretion in CONTEXT): the beacon is the manual JS-snippet form, injected at build time into every HTML entry by a Vite plugin, instead of Cloudflare's dashboard edge injection. Reasons: Phase 5 only deploys to a preview alias, and edge injection is not guaranteed there, so the CSP allowance could not be tested before the Phase 6 public cutover; PITFALLS 8 reports edge injection behaving inconsistently next to a custom `_headers` CSP; and a build-time plugin covers every future entry automatically. Because the manual beacon posts cross-origin, `connect-src` gets `https://cloudflareinsights.com`. Host-only sources are used because the injected beacon URL can carry a version suffix after `beacon.min.js`, which an exact-path CSP source would not match. The real site token is supplied by the user in 05-08 (user_setup there); this plan verifies with a dummy token.

Output: `vite/html-plugins.mjs`, the edited build config and `_headers`, `public/404.html`, the rewritten `datenschutz.html`, an updated `impressum.html`, `scripts/check-analytics.mjs`, and two test files.
</objective>
