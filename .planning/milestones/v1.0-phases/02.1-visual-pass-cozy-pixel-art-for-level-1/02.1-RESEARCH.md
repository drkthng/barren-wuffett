## Summary

Phase 02.1 is a pure visual upgrade — NO mechanics, NO engine changes, NO test breakage. The spike (001-cozy-art-pipeline) has already proven the complete pipeline end-to-end using the exact same Phaser 4 patterns the game uses today. The research task here is to decide five concrete implementation questions and produce a plan the implementer can execute without further ambiguity.

The central architectural decision is **tile size**: the game currently uses 32px tiles with a 15×26 MAP_DATA array; Kenney Tiny Town tiles are natively 16px. The recommended approach (detailed below) is to switch to 16px tiles and a proportionally larger MAP_DATA, matching the spike's proven config and keeping the Preloader / OverworldScene code minimal. This is lower risk than 2x-scaling 32px tiles because it avoids Phaser spritesheet `frameWidth` conflicts and keeps the tileset frame grid predictable.

Character sprites for player, NPCs, dog, and Mr. Market do not exist in Kenney Tiny Town (environment-only pack). The recommended approach is PixelLab AI generation, palette-matched to Kenney's warm tones, with explicit CC0/commercial-OK provenance tracked in a manifest file. This was the spike's recommendation and remains the clearest license-clean path.

**Primary recommendation:** Keep 16px tile size, expand MAP_DATA to 30×52, copy the spike's two-layer (ground + deco) pattern exactly, source character sprites via PixelLab AI palette-matched to Kenney, and ship with a provenance manifest. The 61 existing tests stay green because all changes are in asset files and rendering code — the service/event/save/share layer is untouched.

## Open Questions — Resolved

### Q1: Tile Size Reconciliation (CRITICAL DECISION)

**Current state:** MAP_DATA is 15 cols × 26 rows at 32px tiles = 480×832px world. Preloader loads `omaha_tiles.png` as `spritesheet` with `frameWidth:32, frameHeight:32`. OverworldScene calls `make.tilemap({data:MAP_DATA, tileWidth:32, tileHeight:32})`.

**Kenney Tiny Town:** 16×16 native tiles. Tilemap PNG is 192×176px (12 cols × 11 rows = 132 tiles). The spike used `tileWidth:16, tileHeight:16` and `Scale.FIT` at a 384×256 logical resolution.

**Option A — Scale Kenney 2× via CSS:** Keep 32px `tileWidth/tileHeight`, use `frameWidth:32` in Phaser, but Kenney's packed sheet is actually 16px — Phaser would treat each "frame" as half a tile column, producing wrong tile picks. CSS scaling (`image-rendering:pixelated; width:200%`) cannot fix tileset frame math inside Phaser's tilemap renderer. **This is broken in practice.** [VERIFIED: read OverworldScene.ts + Preloader.ts directly]

**Option B — Double the tilemap data resolution:** Keep 32px display tiles, but scale the Kenney PNG to 384×352 (2× of 192×176) so each tile is 32×32. This requires either a build-time image upscale step or a runtime `setDisplaySize`. The upscale must be pixel-perfect (nearest-neighbour). This works but adds a non-trivial build step (upscale script or Aseprite/GIMP export). MAP_DATA dimensions stay 15×26. [ASSUMED — requires build tooling]

**Option C — Switch to 16px tiles + expand MAP_DATA:** Change OverworldScene to `tileWidth:16, tileHeight:16`, expand MAP_DATA from 15×26 to 30×52 (same physical pixel world = 480×832px), update camera bounds formula. Preloader switches from `spritesheet` to `image` for the tileset (it does not need frameWidth, just an image key). Character spritesheets stay at whatever pixel size they are drawn at. All NPC/dog/boss/trigger pixel coordinates are preserved (same pixel values as before). [VERIFIED: spike used 16px tiles; MAP_DATA coordinate formula confirmed from OverworldScene.ts]

**RECOMMENDED: Option C — 16px tiles, 30×52 MAP_DATA.** Rationale:
- The spike is exactly this setup, proven zero-console-error via Playwright.
- Tileset loads as a plain `image`, no `frameWidth` needed for the ground/deco layers (Phaser's tilemap uses the packed sheet directly).
- Character spritesheets load as `spritesheet` with their own `frameWidth/frameHeight` — independent of tile size.
- World pixel dimensions stay 480×832px. All existing NPC coordinates (e.g. `{x:96, y:96}`) and boss/trigger zone pixel values are unchanged — just remap their tile positions in the new 30×52 grid.
- Camera bounds: `MAP_DATA[0].length * 16, MAP_DATA.length * 16` = `30*16=480, 52*16=832`. Identical pixel world, just different formula.
- The only code edits needed: `Preloader.ts` (load `image` not `spritesheet` for tileset; load spritesheets for characters); `OverworldScene.ts` (`tileWidth:16, tileHeight:16`; `setCollisionByExclusion([-1])` on deco layer instead of `.setCollision([1])` on ground layer); `level-01.ts` (new 30×52 MAP_DATA).

**Dog patrol and NPC pixel coordinates:** These are stored as pixel values in OverworldScene.ts (`DOG_MIN_X=64, DOG_MAX_X=320, DOG_PERIOD=4000`, NPC_DEFS at `{x:96, y:96}` etc., boss zone at `{x:224, y:720}`). Because the world size in pixels does not change, ALL these values carry over unchanged. [VERIFIED: read OverworldScene.ts]

### Q2: Tile-Vocabulary Mapping (MAP_DATA Enrichment Strategy)

**Current state:** MAP_DATA uses 3 abstract values: `0`=ground, `1`=wall/collision, `2`=decoration (non-colliding). OverworldScene renders as a single layer using `setCollision([1])`.

**Spike approach:** Two separate arrays — `ground[][]` (grass + auto-tiled dirt tiles, always one tile per cell, no -1 in this layer) and `deco[][]` (houses, trees, fences; `-1`=empty, specific tile index=deco). `setCollisionByExclusion([-1])` on the deco layer blocks movement at non-empty cells. This is cleaner than the current single-layer approach.

**RECOMMENDED: Replace the single MAP_DATA with two MAP_DATA exports — GROUND_DATA and DECO_DATA — both 30×52.**

Rationale:
- The spike's two-layer model is the standard Phaser pattern and is how the auto-tiler works (you need to know which cells are dirt vs grass to pick the right border tile).
- Current MAP_DATA has `0/1/2` values but the current omaha_tiles tileset is a 68-byte placeholder (1×1 px, black) so the collision/rendering distinction was never visually meaningful. Rewriting MAP_DATA is low-risk.
- With two arrays: GROUND_DATA values are Kenney tile indices (grass=0/1/2, auto-tiled dirt=12..38); DECO_DATA values are Kenney tile indices for collidable decorations (trees, houses, fences) or `-1` for empty.
- NPC positions, dog patrol row, mini-game trigger zone, boss trigger zone and gap rows all live in OverworldScene.ts as pixel coordinates — they do NOT come from MAP_DATA, so rewriting MAP_DATA does not touch them.

**Auto-tiling:** The 8-neighbour dirt auto-tiler from the spike (12 tile indices for TL/TC/TR/ML/MC/MR/BL/BC/BR corners) is implemented as a function that takes the raw dirt boolean grid and outputs the final GROUND_DATA. Run this once at level design time and commit the resulting static array, OR run it in OverworldScene.create() before tilemap construction. The spike ran it at runtime — this is fine for 30×52 = 1560 cells.

**MAP_DATA tile indices reference (Kenney Tiny Town, 12-col packed sheet, 0-indexed):** [VERIFIED: spike README.md + index.html]
- Grass variants: `0` (plain), `1` (flower), `2` (darker flower)
- Dirt auto-tile 3×3: TL=`12`, TC=`13`, TR=`14` / ML=`24`, MC=`25`, MR=`26` / BL=`36`, BC=`37`, BR=`38`
- Dirt full center: `25`
- Big lush green tree (2×2): `7,8` top row, `19,20` bottom row
- Big orange tree (2×2): `10,11` top / `22,23` bottom
- Bush: `5`
- Small tree green: `4`, small tree orange: `3`
- Mushroom: `29`, pebbles: `43`, shrub: `17`
- Red house (3×3): roof `52,53,54` / mid `64,65,66` / base `84,85,86`
- Grey house (3×3): roof `48,49,50` / mid `60,61,62` / base `88,89,90`
- Fence: `44,45,46`, sign: `83`

### Pattern 1: Two-Layer Tilemap (Proven in Spike)

**What:** Ground layer (grass/dirt tiles, no collision) + Deco layer (collidable props, -1 = empty).
**When to use:** Any tilemap with mixed collidable/non-collidable tiles on a shared base.

```typescript
// Source: spike index.html (proven zero-error via Playwright)
// In OverworldScene.create():
const gMap = this.make.tilemap({ data: GROUND_DATA, tileWidth: 16, tileHeight: 16 });
gMap.createLayer(0, gMap.addTilesetImage('tiny_town_tiles', 'tiny_town_tiles', 16, 16, 0, 0), 0, 0);

const dMap = this.make.tilemap({ data: DECO_DATA, tileWidth: 16, tileHeight: 16 });
const dLayer = dMap.createLayer(0, dMap.addTilesetImage('tiny_town_tiles', 'tiny_town_tiles', 16, 16, 0, 0), 0, 0);
if (dLayer) {
  dLayer.setCollisionByExclusion([-1]);
  this.physics.add.collider(this.player.sprite, dLayer);
}
```

### Pattern 2: 4-Direction Walk Animation

**What:** `generateFrameNumbers` per direction, play on velocity update.
**When to use:** Any top-down character that walks.

```typescript
// Source: spike index.html (proven zero-error via Playwright)
// In Preloader.create() or a scene init:
['down','up','left','right'].forEach((dir, i) => {
  this.anims.create({
    key: `player_${dir}`,
    frames: this.anims.generateFrameNumbers('player_sheet', { start: i*2, end: i*2+1 }),
    frameRate: 6,
    repeat: -1,
  });
});

// In Player.update() — add after setVelocity():
if (vx === 0 && vy === 0) {
  this.sprite.anims.stop();
  // idle: first frame of current facing
} else {
  const dir = Math.abs(vx) > Math.abs(vy)
    ? (vx < 0 ? 'left' : 'right')
    : (vy < 0 ? 'up' : 'down');
  this.sprite.anims.play(`player_${dir}`, true);
}
```

### Pattern 3: 8-Neighbour Dirt Auto-Tiler

**What:** Given a boolean `dirt[y][x]` grid, replace each dirt cell with the correct rounded-edge Kenney tile index.

```typescript
// Source: spike index.html (proven zero-error via Playwright)
const DIRT = { tl:12, tc:13, tr:14, ml:24, mc:25, mr:26, bl:36, bc:37, br:38 };
const isD = (x:number, y:number) => x>=0 && y>=0 && x<W && y<H && dirt[y][x];

for (let y = 0; y < H; y++) {
  for (let x = 0; x < W; x++) {
    if (!dirt[y][x]) { groundRow.push(GRASS_VARIANTS[...]); continue; }
    const top=!isD(x,y-1), bot=!isD(x,y+1), lef=!isD(x-1,y), rig=!isD(x+1,y);
    let t = DIRT.mc;
    if (top && lef) t=DIRT.tl; else if (top && rig) t=DIRT.tr;
    else if (bot && lef) t=DIRT.bl; else if (bot && rig) t=DIRT.br;
    else if (top) t=DIRT.tc; else if (bot) t=DIRT.bc;
    else if (lef) t=DIRT.ml; else if (rig) t=DIRT.mr;
    groundRow.push(t);
  }
}
```

### Anti-Patterns to Avoid

- **Tiled "Collection of Images" tileset type:** CLAUDE.md explicitly bans this. Use the single embedded spritesheet (`tilemap_packed.png`). [VERIFIED: CLAUDE.md]
- **Using omaha_tiles as a spritesheet for Kenney tiles:** Kenney's sheet is 16px tiles; using `frameWidth:32` will pick wrong frames. Drop the `spritesheet` loader for the tileset; use `load.image` instead. [VERIFIED: Preloader.ts current code + WR-01 comment explaining this exact bug]
- **Rendering deco tiles on the ground layer with setCollision([1]):** The current single-layer approach works for placeholder art but cannot support a rich cozy tileset where any tile could be either collidable or not. Use two layers.
- **Generating MAP_DATA with randomness in OverworldScene.create():** If scatter placement is random, the map changes every load — NPC zones and trigger zones may be blocked by trees/houses. Pre-compute and commit static GROUND_DATA + DECO_DATA arrays (as the spike's `buildMaps()` was called once to generate, not on every game boot). [ASSUMED — based on spike analysis]
- **Placing collidable tiles on the dog patrol row (y=14 in tile coords, or y=224px in pixels):** The dog patrol gap at row 14 (current MAP_DATA) is the core patience mechanic. The new 30×52 MAP_DATA must preserve a traversable corridor at the equivalent pixel row (y≈224..272px = tile rows 14-17 at 16px). The gap columns must stay open (no collidable DECO_DATA values). ## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Grass↔dirt tile edge transitions | Custom blending / dithering shader | 8-neighbour auto-tiler mapping to Kenney's pre-drawn border tiles | Kenney ships exactly the right 9 border tiles; the spike proved they work cleanly |
| Pixel-perfect 2× upscale of tileset | Custom bilinear/nearest upscale script | Just use Kenney at native 16px (Option C) | Eliminates a build step and an entire class of off-by-one frame errors |
| Character animation state machine | Custom class with IDLE/WALK/RUN states | Phaser's built-in `anims.play(key, true)` + idle `anims.stop()` | Phaser handles de-duplication of play calls; `true` = don't restart if already playing |
| Asset legitimacy checking | Custom npm audit | No new npm packages in Phase 02.1 | N/A |
| CC0 license tracking | Git commit message only | `public/assets/ASSET-MANIFEST.md` markdown table | ART-03 explicitly requires provenance tracking; a committed file is inspectable and testable |

**Key insight:** The entire visual upgrade is data-only from the engine's perspective — swap PNGs, update index arrays. Phaser's existing tilemap/spritesheet/animation APIs handle everything. Resist any temptation to introduce a new library, texture atlas builder, or custom renderer.

## Common Pitfalls

### Pitfall 1: Kenney Tilesheet Has Spacing

**What goes wrong:** `addTilesetImage('tt', 'tt', 16, 16, 0, 0)` — the last two parameters are `margin` and `spacing`. `tilemap_packed.png` (the "packed" variant) has 0 margin and 0 spacing between tiles. The non-packed `tilemap.png` has 1px spacing between tiles. Using the wrong file or wrong spacing value causes tiles to render with 1px offsets and ghosting at each tile boundary. [VERIFIED: Tilesheet.txt + spike used tilemap_packed.png]

**How to avoid:** Always use `tilemap_packed.png`, not `tilemap.png`. Pass `margin:0, spacing:0`.

**Warning signs:** Tiles render with a 1px seam or the wrong tile appears in each cell.

### Pitfall 2: Dog Patrol Row Must Stay Traversable

**What goes wrong:** When placing houses/trees in DECO_DATA, a collidable tile placed at pixel y=224..320 (tile rows 14-20 at 16px) blocks the dog patrol corridor — the player can no longer traverse the gap, breaking the patience mechanic.

**How to avoid:** When building DECO_DATA, preserve rows 13-20 (pixel y=208..320) as clear of collidable deco tiles except for the gap columns. The specific gap is: columns 2 and 6-8 at row 14 in the old 15-col map = columns 4-5 and 12-17 in the new 30-col map. [VERIFIED: level-01.ts row 14 comment + OverworldScene.ts DOG_MIN_X=64, DOG_MAX_X=320]

**Warning signs:** Dog patrol animation works but player cannot pass even during the gap window.

### Pitfall 3: WR-01 — Spritesheet frameWidth Must Match Sprite Pixel Size

**What goes wrong:** Loading a 16×16 character spritesheet with `frameWidth:32` causes Phaser to pick every other column as a frame — wrong tile appears, or only the first frame is used. This is exactly the bug that caused the WR-01 fix comment in `Preloader.ts` ("WR-01 fix: load tileset at 32×32 to match OverworldScene's tileWidth/tileHeight:32"). The inverse problem appears if we keep `frameWidth:32` for character sprites that are 16px wide. [VERIFIED: Preloader.ts WR-01 comment]

**How to avoid:** `frameWidth` and `frameHeight` in `load.spritesheet` must exactly equal the pixel dimensions of one animation frame in the PNG. For 16×16 character sprites: `frameWidth:16, frameHeight:16`.

**Warning signs:** `anims.play('player_down')` shows wrong frame or character sprite is invisible/offset.

### Pitfall 4: NPC Sprites Use `add.image`, Not `add.sprite`

**What goes wrong:** `NPC.ts` uses `scene.add.image()`, which cannot play animations. If NPC spritesheets are loaded and `anims.play()` is called on an Image game object, Phaser silently does nothing (no error).

**How to avoid:** If NPCs need idle animations, change `NPC.ts` to use `scene.add.sprite()` instead. If NPCs are static (single frame), `add.image` is fine and no change is needed. [VERIFIED: NPC.ts uses `scene.add.image(x, y, textureKey)`]

**Recommended:** Keep NPCs as static images for MVP — simpler, avoids NPC.ts structural change, and a single well-drawn frame reads fine at 16×16 scale.

### Pitfall 5: Tile Index Zero Is Valid

**What goes wrong:** Treating tile index `0` as "empty" and using it as the -1 sentinel in DECO_DATA. In Kenney Tiny Town, tile index 0 is plain grass — a valid drawable tile. Using 0 as empty causes grass tiles to appear everywhere in the deco layer instead of empty cells. [VERIFIED: spike index.html — deco array uses -1 for empty]

**How to avoid:** Use `-1` as the empty sentinel in DECO_DATA (Phaser treats negative indices as empty/skip). Never use 0 as empty.

### Pitfall 6: BossScene Uses Static Image — Pose Switch Requires Sprite Upgrade

**What goes wrong:** `BossScene.ts` creates the boss with `this.add.image(cx, 380, 'boss_mr_market')`. If `boss_mr_market.png` is a 2-frame spritesheet (greed/panic poses), `add.image` cannot switch frames. Phase transition from greed→panic will not visually change the boss sprite.

**How to avoid:** Two options: (a) Use two separate PNG files (`boss_mr_market_greed.png` and `boss_mr_market_panic.png`) and call `setTexture('boss_mr_market_panic')` on phase transition — `add.image` supports `setTexture()`; or (b) upgrade `add.image` to `add.sprite()` in BossScene and call `setFrame()`. Option (a) is less invasive. [VERIFIED: BossScene.ts line 116 `this.add.image(cx, 380, 'boss_mr_market')`]

### Pitfall 7: Scatter Randomness in MAP_DATA Generation

**What goes wrong:** If the auto-tiler + scatter (bushes, mushrooms, pebbles) uses `Math.random()` without a seed, the map changes on every OverworldScene.create() call. NPC tap zones, trigger zones, and boss zone proximity are pixel-based, but a tree randomly placed on top of an NPC or a trigger zone makes it unreachable.

**How to avoid:** Pre-compute GROUND_DATA and DECO_DATA once (the implementer runs the scatter logic offline, inspects the result, and commits the static arrays). Do not generate random scatter at runtime in create(). The spike's `buildMaps()` was a generation helper, not a runtime call.
